# GGgame · 低配版规则草案

状态：文字联机版已发布；下方保留原始人机原型的设计记录。当前联机规则与表现以本节更新和 README.md 为准。
本文件记录用户提供的规则，未决项不视为已确认。后续变更以用户说明为准。


## 当前文字联机版更新

- 支持真人房间与电脑对手；源码在 GameFactory-3A，homepage 仅发布构建产物。
- 出拳与结果独立全屏显示；分出胜负时结果页展示 **5 秒**后才允许行动；平局只展示 **1 秒**后全员重来。
- **连续输 7 次，获得 3 步保底**。实现约定：平局不算输也不断连败；赢一次清零；触发保底后重新累计。多人同时满足时各得 3 步。
- 真正退出会立即撤销房间身份；对局中退出视为出局、清空动作与队列。普通成员意外断线仍有 75 秒重连宽限。房主主动退出立即关房；房主断开连接后有 15 秒重连宽限，超时结束整个房间；未检测到断连时，以最后心跳后 45 秒为兜底期限。
- **房主只能在大厅踢人，对局中不能移除成员**；被踢者返回入口，旧身份不能重连。
- 胜负与行动结算有短音效，可静音；声音与动画不参与判定。

## 从规则推导的实现约束

以下是实现约定，不伪称用户逐项确认：

- 每次穿 / 脱操作增减 1 条裤子，护甲在 0～3 之间；零护甲仍存活。
- 一种或三种手势时平局，两种手势时按普通猜拳规则判胜；揭晓前不公开选择。
- 地点是各玩家的家；已出局玩家的家仍保留为地点。
- 每名玩家按提交顺序处理自己的队列；锁只限制自己的下一项，不锁住目标。
- 提交时扣除 1 个可用步数作为预留；入队与执行不重复扣费。不提供取消已提交操作。
- 支持提前安排“拿刀 → 移动 → 脱 → 割”，提交检查会参考自己已有队列；实际成败仍以完成时刻的真实状态为准。
- 提交时非法的操作不进队、不扣步。已开始但结算时因目标移动、穿裤或出局而失效的操作仍耗步数和时间。
- 同时完成的一批行动先按 R21 结算；同一类型再按提交先后打破完全相同时刻的冲突。整批结算后才启动下一项排队操作。这两项细节是当前实现约定。
- 执行、位置变化和结算由单一玩法状态负责，界面动画不决定结果。
- 每次处理精确的事件时间；不能因为渲染帧跨过了多个完成时刻就把它们误判为同时完成。
- 暂停冻结整个模拟；动作剩余时间与等待队列保留。

## 一局的流程草案

这是无剧情的对局游戏，不添加章节故事或背景设定。

| 阶段 | 玩家目标 / 操作 | 反馈 | 下一阶段 |
| --- | --- | --- | --- |
| S01 开局 | 设置参与者，开始一局。 | 所有人位于自己家，裤子 1/3，未持刀。 | S02 |
| S02 猜拳 | 所有存活玩家选手势。 | 先收齐选择，再统一揭晓；平局显示全员重猜。 | 平局留在 S02，否则 S03 |
| S03 行动 | 有步数的玩家同时进行移动、穿、脱、拿刀、割；按各自操作队列到时结算。 | 每人剩余步数、当前行动与等待队列、位置、护甲、持刀和出局状态随动作更新。 | 所有存活玩家步数用完且动作结算后 S02；最后一人存活后 S04 |
| S04 结算 | 查看结果，再开一局。 | 胜者和最终战报；按 Q04 默认条件判定。 | S01 |

一局时长尚未测量；不设置虚构时间、强制回合数或自动判胜。

## 文字动画界面提案

布局参考项目 `rts_in_game` 的局面区与行动区分工，改为文字卡片，不使用其军事地图、美术或实时战斗规则。

| 界面 ID | 内容 | 交互与状态 |
| --- | --- | --- |
| UI01 开局 | GGgame 标题、参与者设置、开始按钮。 | 选择电脑数量、慢热模式，开始人机对局。 |
| UI02 猜拳 | 存活玩家卡片、石头 / 剪刀 / 布按钮。 | 选定、等待、揭晓、平局重猜、胜负与步数奖励。 |
| UI03 行动 | 按地点分组的玩家、自己的可用步数、当前动作进度和等待队列、动作和目标选择。 | 所有人同时操作；忙碌可排队、无步数、目标已移动或出局等原因明确；操作后显示实时文字战报。 |
| UI04 结束 | 胜者、对局结果、再来一局。 | 终局后不再接受对局动作。 |

共享表现元素：

| 资产 ID | 元素 / 来源 | 状态与验收 |
| --- | --- | --- |
| A01 | 玩家卡片与家标签 / 文字、CSS | 名称、位置、裤子、持刀、存活状态始终可辨。 |
| A02 | 三种出拳符号 / 文字、CSS | 同时揭晓，不能提前泄露隐藏选择。 |
| A03 | 裤子计数 / 文字、CSS | 显示 0/3～3/3；零裤子仍显示存活。 |
| A04 | 刀标记 / 文字、CSS | 有刀 / 无刀明确，持有后保持。 |
| A05 | 动作反馈 / CSS 动画与战报 | 移动卡片、护甲增减、获得刀、出局淡出、1/2/3 秒操作进度与队列；多人的反馈可同时播放，减少动态效果时文字反馈仍完整。 |

语义配色提案：护甲蓝色并写明数量；步数金色并写“步”；可处决风险红色并标“无护甲”；持刀紫色并标“有刀”；出局灰色并标“已出局”。玩家身份用姓名，不只依赖颜色。

无需 3D 模型、配音、CG 或付费资产来验证本版玩法。手机窄屏时按上下布局排列局面与操作区，长玩家列表滚动显示。

## 联机战绩

- 从本功能发布后开始统计，每局结束写入。既有历史没有战绩数据，不回填。
- 按完整用户名（去除首尾空白）合并，不区分设备或房间；目前无账号认证。同名的多个参赛席位各计一次。
- 真人对战及人机局均计入真人玩家，电脑不进入排行榜。游玩次数为已结束或中途关闭的参赛局数；正常结束只有最终幸存者增加胜场，普通成员退出算该局未获胜，房主关闭进行中的房间不产生胜者。胜率为胜场 / 游玩次数。
- 击杀只计成功割出局人数，穿裤子只计成功结算的穿裤子动作；开局自带、失败和取消的动作不计。退房也保留本局已完成动作。
- 按胜场降序、游玩次数升序、用户名排序展示前 50 名；可以查询任意完整用户名。
