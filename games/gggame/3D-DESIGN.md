# GGgame 3D 小院试玩

引擎：three_js，使用公开 `ThreeClient` 和 `@a3game/playable`。主工程仍在 web/；Cloudflare 是唯一规则权威，3D 仅消费公开状态。美术方向为卡通剖面小院，当前程序模型是可玩原型资产，后续可替换。

## 一局流程与验收

| ID / 阶段 | 玩家行为与画面 | 进入 / 退出 | 验收 |
|---|---|---|---|
| R1 / 大厅 | 加入、添加电脑、踢人、看小院 | 已连接 / 房主开始 | 成员变化更新场景；保留退出 |
| R2 / 出拳 | 独立全屏选择石剪布 | 开局或新轮 / 收齐出拳 | 不显示未揭晓的拳型 |
| R3 / 结果 | 每人步数、胜负音效、保底提示 | 收齐 / 服务端胜负 5 秒、平局 1 秒 | 沿用现有实现 |
| R4 / 行动 | 点房屋选择目的地并移动，点小人选择对手；安排五种动作 | 结果结束 / 步数用尽 | 动画不结算规则；移动立即独立户外，2 秒到达；队列与失败正确 |
| R5 / 结束 | 倒地、赢家庆祝、重开或退出 | 最后幸存者 / 重开或离开 | 无残留模型和动画 |

这是非叙事派对游戏，不增加剧情章节或虚构时间。一局时长由玩家出拳和行动决定，不设固定分钟数。

## 画面与输入

参照 rts 的俯视世界 + 下方命令区域；桌面先保护 3D 视口，手机画面下方排操作。提供缩放、旋转、全景、找自己。姓名标签可点，房屋标签选择目的地；移动仍需可用步数。原文字状态及操作作为可访问的详细视图和 WebGL 不可用时的降级。

屏幕绑定：members、game.players、phase、active、events、result；输入只调用现有 send(type,target)。模型按稳定玩家 ID 关联。渲染插值与真实状态分开，不创建本地 GGGame 副本。服务器 active.from 是公开移动起点元数据，供刷新中途恢复轨迹。

范围外：自由 WASD 跑动、碰撞战斗、门、付费生成模型、角色养成和装备商店。
